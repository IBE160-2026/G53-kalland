**PR title:** Story 2.3: Contacts set their password from a setup link

**PR description:**

> ## What and why
> A contact added in 2.2 had no way to log in. Staff now hand each contact a setup link themselves, since the app sends no email (FR-4, FR-5, UJ-4).
> - Creating a contact also creates a setup link in the same transaction (`auth.issueSetupLink(tx, userId)`). The Add contact page then shows "Contact added", the link with "Copy link" and a "Copied" status, and "Back to <client>", instead of redirecting.
> - Each contact row has "New setup link" (also for a password reset). The new link's panel opens under the row and shows when the link expires (Oslo time). A new link cancels the contact's earlier unused ones.
> - `/setup/<token>` is a public page with one centred form. A password of 12–1024 characters uses up the link, stores an argon2id hash, ends all the user's other sessions in the same transaction, and logs the contact in on `/overview`. A short password gives an inline error, and the link stays valid.
> - A used, expired (7 days), replaced or unknown link goes to Login with exactly "Link expired. Contact the agency for a new one." (S8). A deactivated contact, or a contact of an inactive client, gets the inactive message, and the link stays unused.
> - Only the SHA-256 of a token is stored. Tokens never reach the app log, and Next's dev request log skips `/setup/` paths. The page sends no Referer.
> - Migration `0009` adds `setup_links`. Using a link is a conditional update, and issuing one locks the user row, so parallel submits or issues leave exactly one working link.
>
