**Why it makes sense in Graphite:**
- In round 2 you picked a plain price over an accent-coloured one, but that was next to a blue accent.

**The caveat:** Graphite's status colours are small, saturated signals: green success, red danger, orange warning, blue info. The price colour must not look like any of them:

**Clients on public images is more than a UX change.** The 2026-11-18 PRD doesn't allow it. In FR-21, only *Restricted* images have a client list. A public image becomes "own" for a client only through a licence (access table row A3), which today means the client bought it, or downloaded it once if it's free. So this changes the access model, and needs a PRD update plus a D-xxx.

There are two ways to model it:

**A. Staff grant a licence ("Owned by").** Recommended.
- Staff add clients to an "Owned by" list on any image. Each entry records a 0 USD licence for that client, marked as granted by staff.
- The access table stays as it is: rows A3, A6, A8 and A10 already make licence holders owners.
- Other clients still see the image and can buy it if it's public and paid.
- It survives later changes to visibility or price, because licences last (FR-24). Revoke (FR-25) removes an owner.
- PRD change: one new FR for staff-granted licences. SC-1 gets a few new test cases.

**B. A client list on public images.**
- The visibility client list also appears for Public, with the meaning "these clients own it".
- The list then means two things: for *Restricted* it means "who can see it" (and they still have to buy if it's paid); for *Public* it means "who owns it".
- PRD change: FR-21, rows A1–A3 of the access table, new edge rules, and more SC-1 tests.

I recommend **A**. It fits the PRD's core bet that a licence that lasts covers both commissioned work and stock sales. It keeps the access table and its tests stable.
