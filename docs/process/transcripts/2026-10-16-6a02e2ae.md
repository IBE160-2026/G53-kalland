All three are logged. Using the subscriptions you already pay for at work is a solid reason, and it belongs in the brief. A map view by location is a good stage-2 feature, and under your rule it needs nothing more in v1 than storing latitude and longitude as fields.

Writing edits back into the file has a consequence you probably haven't seen yet. It collides with two decisions you've already made.

**Problem: editing the file changes its hash.**
- **Duplicate detection breaks.** Say you upload `beach.jpg` and correct its caption, and the edit is written into the stored file. Someone then uploads the original `beach.jpg` again. Its hash no longer matches the stored file, so the duplicate gets through. Your success criterion "an identical upload is rejected" fails on the first metadata edit.
- **Versioning gets muddy.** Is a caption fix a new *file version*? If not, the stored file changed under a version that claims to be unchanged. If yes, every typo creates a version.

**A way out.** Ask yourself what the need really is: does the *stored master* have to change, or do the *files that leave the system* have to carry correct metadata?

- **Write on export:** store the original file unchanged, and keep the database as the source of truth for metadata. When a file is downloaded, the current metadata, including your corrections, is written into the copy that goes out. The hash stays stable, versions stay clean, and the client gets a correct file.
- **Write on edit:** edits change the stored file. Duplicate detection then has to hash only the *pixel data* and ignore metadata, which is more work and a detail for the architecture stage.

Write on export also helps with GPS. You keep coordinates for your own map, and you can decide per download whether they go into the client's copy.

**Questions:**

1. **Write on export or write on edit?** I recommend write on export, unless you have a case where the stored master itself has to be correct, for example other tools reading straight from the storage folder.
2. **GPS in client downloads:** keep it or strip it? Think of a portrait shoot at someone's home.
3. **Still open: which one real provider ships in v1, with the mock?** Your CLI reasoning points to the Claude CLI, since it's free for you to test. Gemini and Ollama would then move to stage 2.
