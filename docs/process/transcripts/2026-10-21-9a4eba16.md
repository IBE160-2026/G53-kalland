### What you can do now, before any building

##### 1. Sample images (most important, 3–5 h)
- **Check the license carefully.** The Unsplash and Pexels licenses forbid selling the photos unchanged and building a competing service. A stock storefront that sells images is exactly that case. Use **CC0 or public-domain images** (for example Wikimedia Commons, or Openverse filtered to CC0), or better, **your own photos**.
- **Your own phone photos** are the best choice for testing metadata. Stock sites often strip EXIF, while your phone keeps GPS and camera data, so the "no GPS in downloads" test has something to remove.
- Keep the committed set small, about 20–40 images resized to around 1600 px and under about 500 KB each. The ~500-image scale test can be generated later and kept out of the repo.
- Collect **edge cases** on purpose:
  - a byte-identical duplicate pair
  - two different files with the same filename
  - an image with existing IPTC keywords
  - a corrupt file
  - a non-image file renamed to `.jpg`
  - a very large file
  - possibly a HEIC file, to force a decision on supported formats
- Keep a list of each image's source, license and author. It feeds the README later.

##### 2. Dummy content (2–3 h)
- About 10 fictional client companies with fake contact details, never real agency clients.
- A table planning which images are restricted to which client, and at what prices. Make sure every visibility × price combination is covered, including client A against client B.
- Login details for the test users: one admin and two clients.
- All of this becomes seed data later, so prepare it in your own notes for now.

##### 3. Questions for the agency (1–2 h, a conversation with colleagues)
Answer these before the PRD session and it goes much faster:
- If staff change an image's visibility after a client has bought it, does the client keep access? This is the brief's open question.
- Does one client company have one login or several users?
- Currency, typical price levels, and whether prices are set per image.
- Which file types and maximum sizes the agency actually uses (RAW, TIFF, PSD, HEIC?).
- Which words staff actually search with, to get realistic keywords.
- Can a purchased image be deleted?

Don't name people in the repo; describe them by role.

##### 4. Sketches and wireframes (2–4 h)
The teacher asked for the **upload flow and the client portal to be sketched early**. Paper sketches are fine (photograph them), or use Excalidraw or Figma. Cover:
- upload, then reviewing and editing the AI metadata
- the duplicate warning
- the client dashboard with search, a paid preview and the buy action
- purchase history for the client and the purchase log for the admin

They count as evidence of design work under criterion 4 and are input to `bmad-ux`.

##### 5. Draft of the manual test plan (1–2 h)
Write the access matrix (visibility × price × client on or off the list × bought or not) as test cases with expected results. The automated tests will be based on it, and it shows planned quality work under criterion 3.

##### 6. Tools and accounts (1–2 h)
- **Check whether the Claude Code CLI can describe an image when run without interaction.** Try it on one image with `claude -p`, and save the prompt and output as research. The architecture of the CLI provider depends on the answer, so this is the most important technical unknown.
- Install `exiftool` to inspect the metadata in your sample images.
- Note which versions of Node or Python are on your machine. They are input to the stack decision.
- Arrange a **clean machine** for the final README test: a friend's laptop, a new macOS user account, or a VM. Arranging it early is much easier than in December.
- Have an Excalidraw or Figma account ready for the sketches.

##### 7. Ongoing habits
- Put a weekly `/grading-check` in your calendar.
- Keep a short reflection journal: what the AI got wrong and what you corrected. That is raw material for part 2 and for criterion 1.
